# 08 · 验收标准与实施计划

## 1. 等价性验收清单

对照「该源单独部署一个现有单源集群」，逐条验收（每条对应 MS 测试组，
§2；全部通过是本特性交付的定义）：

| # | 维度 | 验收标准 |
|---|------|---------|
| E1 | 数据一致性 | 双源并行写各自源 → 各自目标数据与单集群部署逐行一致（含 UPDATE/DELETE/PK 变更/大事务）；`verify` mismatch=0（脱敏列除外） |
| E2 | 全量+增量交接 | 每个源独立完成快照 → 增量无缝衔接；交接窗口写入零丢失（06 §1 不变式逐源成立） |
| E3 | 断点与重启 | 全量中途杀进程/杀 leader：会话失配表整表重扫、已 done 表不重跑；增量按各自水位重放收敛 |
| E4 | HA 接管 | 双节点部署，杀 leader：两个源均在 TTL+10s 内接管、窗口期写入零丢失、旧 leader 位点写被门槛拒 |
| E5 | 失败隔离 | 源 A 源库停机 → A 重连退避/熔断 PAUSED，源 B 持续同步无中断、无背压传导；A 恢复后自动续传 |
| E6 | DDL 审批 | 源 A 的 DDL pending 只冻结源 A 位点，源 B 继续推进；approve/skip 幂等（重启重放命中已决记录） |
| E7 | 人工暂停/恢复 | 逐源 pause（跨重启/失位保持）/resume；暂停期间改该源位点后恢复生效 |
| E8 | 位点操作 | 逐源 SET-POSITION 回拨重放、GTID↔file:pos 迁移（8MiB 门槛）语义与单集群一致 |
| E9 | restock | 逐源逐表 restock + 重启 → 仅该表重扫，其他源与其他表不动 |
| E10 | 投递语义 | MQ：每源消息按主键有序、event_id 去重可用；MySQL：幂等 upsert 收敛重放 |
| E11 | 背压 | 源 A 下游停 → A 队列打满反压 A 拉取，进程 RSS 不超预算；源 B lag 不受影响 |
| E12 | 配置与迁移 | v1 配置零修改升级 → 行为与升级前一致；etcd 键迁移幂等（重复启动不重复搬）、迁移后位点连续 |
| E13 | 防脑裂 | 分区旧 leader 对任一源的位点/标记写入全部被拒（gate 锚唯一性） |
| E14 | 操作面 | 全部写操作 confirm/口令/审计齐全，审计条目带 source 可追溯 |

显式声明的不完全等价（01 §5，验收不视为缺陷）：资源集中（容量预算
落实即可）、leader 切换/重启的全部源同时性。

## 3. 实施计划（五阶段，每阶段可独立合入）

### P1 · 配置与规范化（无行为变化）

- `internal/config`：v2 结构 + v1 包装规范化 + 校验 V1~V6（含跨源目标
  不相交）+ README 增补字段文档。
- 出口：单源 v1/v2 配置等价加载，全部现行测试绿。

### P2 · 运行时多源化

- `cmd/gocdc`：buildSourceComponents、sourceTable（state.go 改造）、
  runLeaderFlow 多源 goroutine、源 failed 重试、server_id 派生、
  优雅停机并行 drain、共享 GC。
- `internal/*` 包**预期零改动**（store/gate/marker 已按实例组织）；
  schema/transform/sink 逐源实例化。
- 出口：单源行为与现主干完全一致（回归全量测试）；双源手工冒烟通过。

### P3 · etcd 迁移 + API

- 键迁移（幂等 CAS + 完成标记 + 审计）；v2 路由 + 兼容层 + DTO source
  字段；standby restock panic 边角修复。
- 出口：MS-11~MS-14 绿；升级演练（v1 配置 + 存量 etcd 数据 → 新二进制）通过。

### P4 · 前端 + 可观测

- 源选择器、总控台聚合视图、各页 source 化；指标 label 化 + Grafana
  面板/告警更新；日志 source 字段与新增事件。
- 出口：web-check/web-test 绿；演示截图更新（README 界面预览）。

### P5 · 验收与交付

- MS-01~MS-16 全量执行（L3 按记忆惯例前台逐组跑）；
  `deploy/docker-compose.multi-source.yml` 演示；GUIDE/RUNBOOK/TESTCASES/
  arch（03/13 增补多源章节）文档同步；README 特性说明更新。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 进程级资源集中（N 源内存/连接/CPU） | OOM/目标库连接打爆 | 容量公式与连接预算入 GUIDE 部署 checklist（05 §5）；源数硬上限 64；`gocdc_sources`/`gocdc_source_up` 告警；压测基线扩展到 N=8 |
| 指标 label 化破坏现有面板/告警 | 监控盲窗 | PromQL 兼容性说明（07 §1）+ 面板随版本同步更新；升级检查单含此项 |
| etcd 迁移后降级丢位点 | 回滚困难 | 迁移前位点值入审计日志（可完整重建）；RUNBOOK 三步搬回流程；完成标记含搬迁明细 |
| 单进程重启全部源同时切换 | 窗口期集中 | 文档如实声明（01 §5）；需要错峰的场景保留多 cluster 形态共存 |
| 多份源密码管理出错（ENV 缺失/填错源） | 启动失败/连错库 | ENV 缺失错误带 `[sources/{sid}]` 定位；`/config` 打码视图可核对每源地址；建议独立变量名（03 §6） |
| 配置体量膨胀（64 个源 × N 规则） | 校验/可读性 | YAML 锚点复用公共段；配置编辑器列开放问题（08 §5） |
| 长尾兼容（外部脚本依赖旧 API 顶层字段） | 升级后脚本失效 | 弃用窗口 ≥ 2 个小版本 + 升级说明列出全部变更端点 |

## 5. 开放问题（本 PRD 不决，实现期评审定）

1. **Web 配置编辑器**：多源配置变长后 etcdctl 直改 + 重启的体验进一步
   恶化；13 §4 的 `PUT /config`（写回 etcd + 提示重启）是否随本特性补齐。
2. **源级选主**（04 §6）：若单 leader 承载 64 个源出现资源瓶颈或需要
   按源灰度切换，再评估 `{sources}/{sid}/leader` 方案。
3. **`/overview`、`/nodes`、`/stock` 端点**（13 §4 遗留缺口）：多源聚合
   总览页（06 §2.2）已覆盖其核心诉求的 60%，完整实现优先级是否提升。
4. **同源实例多源的 FTWRL 相互影响**（05 §4-1）：罕见拓扑，若实测出现
   快照互相阻塞，考虑同 addr 源的全量互斥锁（配置显式开启）。
5. **源热插拔**：不改配置文件结构的前提下，是否支持「子配置引用」
  （config key 下挂 per-source 子 key，进程 watch 子 key 集合决定源增删）——
   与「不热更」的现行决策冲突，需产品层面重新裁决。
